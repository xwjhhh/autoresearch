# AutoResearch 版本发布目录

`versions/` 是唯一发布和版本归档位置。当前版本 **0.7.1** 的正式安装包位于 `0.7.1/windows/AutoResearch-0.7.1-Windows-Setup.exe`；`latest.json` 记录最近一次归档的位置与 SHA-256。

## 固定结构

```text
versions/
  README.md
  latest.json
  .build/windows/          # 唯一临时构建目录；成功归档后自动移走
  <版本号>/
    version.json          # 版本、归档时间、安装包大小、SHA-256、代码核验清单
    source/               # 当前发布对应的源码快照和构建配置
    windows/              # 正式安装包、blockmap、win-unpacked 和验证记录
    docs/                 # 该版本说明、修复报告和发布记录
    packages/             # 该版本源码 ZIP、功能阅读包等附属交付物
    history/<时间标记>/   # 同版本旧构建、旧源码或未完成构建，原样保留
  _legacy/                # 无法确定版本的旧构建残留，单独注明
```

`source/` 和 `windows/` 总是指向该版本当前发布；`history/` 中的内容不能当成最新版。旧版本已存在的 `0.2.1/hotfix/` 保留原路径。

## 发布命令

- 新版本：先执行 `npm version <新版本号> --no-git-tag-version`，再执行 `npm run dist:win`。开始构建前检查版本号和目标路径，构建完成后自动归档。
- 研究者授权同版本重发：执行 `npm run dist:win:replace`，版本号不变，旧构建自动进入本版本 `history/`，不会删除历史。
- 已有完整临时构建只需归档：执行 `npm run archive:version`；同版本已存在时需显式加 `-- --replace-existing`。
- 不直接把根目录 `release*` 或自行指定的临时文件夹当成交付位置；不要在根目录放版本安装包、版本 ZIP 和修复说明。

归档校验 `package.json` / `package-lock.json` / 打包应用的版本一致，并逐文件核对 `electron/`、`dist/`、`assets/` 与 `app.asar`。安装包计算 SHA-256。归档失败时尽量恢复旧目录和临时构建；恢复不完整时保留中间文件并明确报错。`latest.json` 表示最近成功归档，而非自动判断所有历史版本中最大的语义版本号。

## 数据边界

`data/` 保存真实课题、Conda 环境、实验输出和聊天记录，不移动、不压缩、不复制进发布归档。源码快照采用明确的文件清单，不扫描整个工作区；不包含 `node_modules/`、其他版本目录、输入附件和凭据。`dist/` 是网页构建结果，仍保留在工作目录供开发运行，不是另一个发布目录。
